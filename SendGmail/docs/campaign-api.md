# Campaign API — Local Development

Base URL: http://localhost:8080

## Prerequisites

- MySQL is running on port 3306.
- Database `bulk_email` and application user are configured.
- DB_PASSWORD is available to the application process.
- Flyway migration V1 has completed successfully.

## Create a campaign

POST /api/v1/campaigns
Content-Type: application/json

Example request:

```json
{
  "name": "Placement Update",
  "subject": "Interview Schedule",
  "message": "Your interview is scheduled for Monday."
}
```

Success: HTTP 201 Created

```json
{
  "id": 1,
  "name": "Placement Update",
  "status": "DRAFT"
}
```

The ID is generated by MySQL and may differ from this example.

Validation:
- name: required, maximum 150 characters
- subject: required, maximum 200 characters
- message: required, maximum 10000 characters
- Invalid requests return HTTP 400.

Creating a campaign saves its content. It does not send emails.

Repeated valid POST requests currently create separate campaigns.
Request idempotency is not implemented yet.

## Fetch a campaign

GET /api/v1/campaigns/{id}

Success: HTTP 200 OK

```json
{
  "id": 1,
  "name": "Placement Update",
  "subject": "Interview Schedule",
  "message": "Your interview is scheduled for Monday.",
  "status": "DRAFT"
}
```

The API's message field maps to the database's body column.

An ID that does not exist returns HTTP 404:

```json
{
  "status": 404,
  "message": "Campaign not found with id: 999999"
}
```

## Application flow

1. CampaignController receives the HTTP request.
2. Bean Validation checks the create request.
3. CampaignService coordinates the operation.
4. CampaignRepository executes parameterized SQL using JdbcTemplate.
5. MySQL stores or retrieves the campaign.
6. The controller returns the response.
7. ApiExceptionHandler maps supported exceptions to error responses.

## Schema management

Flyway applies versioned migrations during application startup.

- V1__create_campaign.sql creates the campaign table.
- flyway_schema_history records applied migrations.
- Applied migrations must not be edited.
- Future schema changes require new migration files.

## Current limitations

- No recipient import or background sending yet.
- No retries, rate limiting, or delivery tracking yet.
- Campaign endpoints do not yet enforce authentication or ownership.
- Use the current API only for local development.
